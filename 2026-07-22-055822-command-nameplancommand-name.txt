     学习资源 & 工作坊 — 第一版 PRD 设计计划

     Context

     /resource-hub（学习资源）和
     /workshop（工作坊）目前都是纯前端展示页，数据全部硬编码在 page.tsx
     里，彼此、以及和后台之间都没有真实的增删改查闭环：

     - 学习资源（src/app/resource-hub/page.tsx，826行）：4个静态板块（名师课堂/
     教学方法精选/即用工具包/教学情境演练），数据是页面内 4
     个数组常量，无发布状态、无后台管理入口。仓库里另有一份孤立未使用的
     src/data/mockData.ts（对应内部旧 PRD
     的"资源中心"设想：核心工具/能力资源包/案例库），从未被任何页面引用。
     - 工作坊（src/app/workshop/page.tsx，323行）：5张写死的工作坊卡片，点击跳转
     /workshop/[id] 但该路由不存在（会 404），卡片上的"继续学习"按钮没有
     onClick，参与人数/进度全是假数据。无 /admin 端管理能力。
     - /admin 现有 courses、teachers
     两个管理页，均无关联资源/工作坊的字段或入口。

     用户已确认本轮目标：不追求对齐内部旧 PRD 
     里"资源中心+我的发展+发布至LMS"的深度打通设想（那份构想更偏向"PD 内容反哺
     LMS"，与当前"两个板块自身流程不完整"是两个不同问题）；本轮聚焦让学习资源和
     工作坊各自成为一个内部逻辑自洽、有后台管理、前端交互完整的独立模块，产出可
     以直接讨论/评审的第一版 PRD 文档（先出文档，不写代码）。

     已确认的关键决策

     1. 学习资源内容来源：平台方（运营/内容团队）精选为主，后台统一管理增删改；
     教师端 v1 只读 + （可选）收藏，不做教师个人上传/知识库。
     2. 工作坊定位：展示 + 教师成果画廊，v1
     不做报名/RSVP。核心场景——詹老师团队本身就在到处做线下工作坊，线上模块是"留
     痕+展示"载体，因此每场工作坊有两种材料模式：
       -
     独立模式：团队直接上传课件、资料、活动照片；老师自行上传自己的产出成果。
       - 关联课程模式：核心课件 = 已关联的某门 LMS
     课程（不用重复上传课件本身），但仍支持团队补充上传其他资料/照片，且系统尝试
     自动关联老师们在该课程下的过程性成果，同时也支持老师手动上传。
       - 两种模式共用同一套"资料区 +
     成果画廊"结构，只是资料/成果的来源不同——保证"简单又通用"。
     3. 不做的事（v1 
     明确排除）：工作坊报名/RSVP、内容审核工作流、学习资源的教师个人上传、与 LMS
     的深度双向数据打通（如"发布至LMS"）。

     产出物

     两份 PRD 文档（Markdown，含背景/现状/范围/数据模型/后台设计/前端交互/空状态
     设计/明确不做的事），保存到：
     - docs/学习资源-PRD-v1-{YYYYMMDDHHmm}.md
     - docs/工作坊-PRD-v1-{YYYYMMDDHHmm}.md
     （按用户全局规则，文件名带生成时间戳）

     PRD 1：学习资源（resource-hub）

     范围

     沿用现有 4 个板块的信息架构（名师课堂 / 教学方法精选 / 即用工具包 /
     教学情境演练），不重新发明分类体系——但把"数据从哪来"这件事从硬编码数组改造
     成统一的资源数据模型 + 后台管理。

     数据模型（讨论稿，供 PRD 呈现，非最终代码）

     一个 LearningResource 基础字段（id、type、标题、简介、封面图、学科/学段标签
     、状态：草稿/已发布、排序权重、创建时间）+ 按 type 区分的专属字段：
     - video（名师课堂）：教师/学校、时长、视频源地址、要点时间轴（对应现有
     highlights）
     - method（教学方法精选）：图文讲解内容、关联案例列表（对应现有
     solutions/caseStudies）
     - toolkit（即用工具包）：文件类型、下载地址/文件
     - simulation（教学情境演练）：场景描述、外链地址（目前是硬编码的
     aichat.cocorobo.cn 链接，改为后台可配置）

     后台管理设计（新增 /admin/resources）

     - 列表页：按 4 个 type 筛选 + 学科/状态筛选，表格/卡片形式，显示发布状态
     - 新建/编辑：根据选择的 type 动态渲染对应表单字段（复用 /admin/courses
     现有的表单/筛选交互模式）
     - 支持草稿/发布状态切换、排序（决定前端展示顺序）
     - 不做审核流程（内容团队自己既是创建者也是发布者，v1 无需二级审批）

     前端交互设计（按现有 4 个板块分别说明）

     - 名师课堂：卡片 → 弹窗内嵌播放器（现有交互保留）
     - 教学方法精选：左侧列表选中 → 右侧详情面板展示图文+案例（现有交互保留）
     - 即用工具包：卡片 → 直接下载（现有交互保留）
     - 教学情境演练：卡片 →
     "开始训练"跳转外部链接（现有交互保留，链接从后台配置读取而非硬编码）

     空状态设计

     某个 type 下后台未发布任何内容时，对应板块展示"内容筹备中"的占位态，而不是
     空白或报错。

     明确不做（v1）

     - 教师个人上传资料 / 个人知识库
     - "收藏"跨页面聚合（我的发展页）
     - 与 LMS 创课流程的字段级打通（如"以此为模板创建教案"预填）

     PRD 2：工作坊（workshop）

     范围

     展示 + 教师成果画廊。修复当前"点击卡片 404"的断链（需要真正建出
     /workshop/[id] 详情页），不做报名/RSVP。

     数据模型（讨论稿）

     - Workshop：基础信息（标题、主题、时间、地点/线上线下、讲师/团队、简介、封
     面、状态：即将开始/进行中/已结束——由时间范围自动推导而非手填）+ 可选字段
     linkedCourseId（关联的 LMS 课程，下拉自 /admin/courses 现有课程列表）
     - WorkshopMaterial：工作坊资料（类型：课件/议程/照片/其他，上传者=团队/admi
     n，与 Workshop 一对多）——两种模式下都可以有，只是"关联模式"下课件本身可以直
     接复用课程内容，不强制重复上传
     - WorkshopArtifact：教师成果（标题、描述、文件/图片/链接、老师、上传时间，s
     ource: 'manual' | 'course-synced'）——手动上传和系统同步共用同一个模型和同一
     个画廊展示位，只是来源标签不同

     关于"系统自动关联老师过程性成果"的实现说明（重要，需要在 PRD 里向用户挑明）

     现有 /admin/courses 的课程数据模型里没有"任教老师名单"这类字段（只有学科/年
     级/学生数等聚合数据），无法做到真正的自动抓取。v1 PRD 里会如实说明：
     - 关联课程模式下，"自动同步"在 v1 用 mock 数据模拟效果（预置几条打上"自动同
     步"标签的成果卡片），实现"这个模块看起来是打通的"这一产品效果；
     - 但数据模型上把 source
     字段和展示组件都按未来接真实数据的方式设计好，方便二期换成真实的 LMS
     课程-教师关联数据。
     这一点会作为一个需要用户明确知晓/认可的假设写入 PRD，而不是悄悄简化。

     后台管理设计（新增 /admin/workshops）

     - 创建/编辑工作坊：基础信息表单 + "关联课程"下拉（可留空）
     - 资料管理：上传/删除课件、议程、照片，无需强绑定关联模式
     - 成果墙管理：查看/删除老师上传的成果（轻量内容管理，不做审核工作流）

     前端页面设计

     - 列表页（/workshop，在现有 4 卡片基础上调整）：去掉"进度%"这类假报名指标，
     改为展示真实可统计的信息（资料数量、成果数量、时间、地点）
     - 详情页（新增，修复现有 404） /workshop/[id]：
       - 工作坊信息区（时间/地点/讲师/简介，若关联课程则展示课程入口链接）
       - 资料区：团队上传的课件/议程/照片
       - 成果画廊区：瀑布流展示 WorkshopArtifact（手动上传 +
     自动同步混排，自动同步的打标签区分）
       - "上传我的成果"按钮 →
     简单表单（标题、描述、文件/图片或链接）——面向所有教师开放，无需审核

     空状态设计

     - 团队尚未上传任何资料，也未关联课程 → 资料区展示"资料筹备中"
     - 成果墙为空 → 展示"还没有老师分享成果，来做第一个"引导上传

     明确不做（v1）

     - 报名/RSVP、人数限制、签到
     - 内容审核工作流
     - 深度 LMS 数据打通（除"关联课程"这个轻量指针外）
