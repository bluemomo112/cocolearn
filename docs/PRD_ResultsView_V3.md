## 一、核心设计原则

### 1.1 数据可用性驱动的UI设计

**核心理念**: 板块可变，根据实际数据可用性动态展示

**设计原则**:

1. **统计数据优先**: 必然可以采集到的统计性信息优先展示
2. **分析数据可选**: 可能不存在的分析性信息做成可变板块
3. **确定性排序**: 越确定的数据越放在前面
4. **初始数据保证**: 每个学生都有初始基线数据
5. **变动为主**: 每次课主要显示变动和增量

### 1.2 能力维度的可选性

**关键认知转变**: 能力维度评估是**可选的**，而非必需的

**现实情况**:

- 客观题主要检测知识掌握，不一定涉及能力维度
- 简单题目 (如 1+1=?) 没有能力维度测评
- 教师可能不配置能力维度
- 不同学科有不同的评估维度
- 存在跨学科通用能力维度

**设计应对**:

- 能力维度评估板块为**可选板块**
- 未配置能力维度时，该板块不显示
- 统计数据 (进度、得分、时长等) 始终可用

## 二、数据分层模型

### 2.1 数据确定性分层

将所有数据按确定性分为三层:

#### 第一层: 必然存在的统计数据 (100%确定)

这些数据只要学生开始学习就一定会产生:

```typescript
interface GuaranteedStatistics {
  // 学生基本信息
  studentId: string;
  studentName: string;
  enrolledAt: Date;  // 绑定课程时间

  // 学习行为统计 (必然存在)
  learningStats: {
    totalStudyTime: number;        // 总学习时长 (秒)
    lastActiveAt: Date | null;     // 最后活跃时间
    loginCount: number;            // 登录次数
    resourceAccessCount: number;   // 资源访问次数
  };

  // 任务完成统计 (必然存在)
  taskStats: {
    totalTasks: number;            // 总任务数
    completedTasks: number;        // 已完成任务数
    progress: number;              // 完成进度 (0-100)
  };

  // 对话统计 (必然存在)
  dialogueStats: {
    totalMessages: number;         // 总消息数
    studentMessages: number;       // 学生发送的消息数
    averageMessageLength: number;  // 平均消息长度
  };
}
```

**UI展示**: 这些数据**始终显示**，即使学生刚绑定课程还未开始学习

#### 第二层: 条件存在的得分数据 (条件确定)

这些数据在特定条件下存在:

```typescript
interface ConditionalScoreData {
  // 客观题得分 (有客观题时存在)
  objectiveScores?: {
    totalQuizzes: number;          // 客观题总数
    completedQuizzes: number;      // 已完成客观题数
    averageScore: number;          // 平均得分 (0-100)
    scoreDistribution: {           // 得分分布
      excellent: number;  // 90-100分人数
      good: number;       // 80-89分人数
      pass: number;       // 60-79分人数
      fail: number;       // 0-59分人数
    };
  };

  // 主观题得分 (启用AI批改或教师批改时存在)
  subjectiveScores?: {
    totalAssignments: number;      // 主观题总数
    gradedAssignments: number;     // 已批改主观题数
    averageScore: number;          // 平均得分 (0-100)
  };
}
```

**UI展示**:

- 有数据时显示对应板块
- 无数据时不显示该板块
- 显示条件说明 (如 "课程中无客观题")

#### 第三层: 可选的能力评估数据 (完全可选)

这些数据只在教师配置了能力维度时存在:

```typescript
interface OptionalCompetencyData {
  // 学科能力维度 (教师配置时存在)
  subjectCompetencies?: {
    subjectId: string;             // 学科ID (如 "math", "chinese")
    dimensions: SubjectDimension[]; // 学科特定维度
  };

  // 跨学科能力维度 (教师配置时存在)
  crossDisciplinaryCompetencies?: {
    dimensions: CompetencyDimension[]; // 通用能力维度
  };

  // AI识别的能力表现 (AI分析时存在)
  detectedCompetencies?: {
    dimensions: DetectedDimension[];
    confidence: number;            // AI置信度
  };
}

// 学科维度定义
interface SubjectDimension {
  id: string;
  name: string;                    // 如 "数学运算能力"
  rating: 1 | 2 | 3 | 4;          // 星级评分
  description: string;
  evidence: string[];
}

// 跨学科能力维度定义
interface CompetencyDimension {
  type: CompetencyType;            // 通用能力类型
  rating: 1 | 2 | 3 | 4;
  description: string;
  evidence: string[];
}

// 通用能力类型 (保留原有6种)
type CompetencyType =
  | 'critical_thinking'
  | 'information_synthesis'
  | 'metacognition'
  | 'question_quality'
  | 'creativity'
  | 'persistence';
```

**UI展示**:

- 教师未配置能力维度时，整个能力评估板块不显示
- 配置了学科维度时，显示学科能力板块
- 配置了跨学科维度时，显示跨学科能力板块
- AI识别到额外能力时，显示AI发现板块

## 三、可变板块系统设计

### 3.1 板块优先级和显示逻辑

按确定性从高到低排列板块:

#### 优先级1: 必然存在的统计板块 (始终显示)

1. **班级概览卡片**

   - 显示条件: 始终显示
   - 数据来源: 学生绑定信息
   - 内容: 绑定学生数、平均进度、平均学习时长
2. **学生状态分布**

   - 显示条件: 始终显示
   - 数据来源: 学生学习状态
   - 内容: 未开始/进行中/已完成/需要关注的学生数
3. **任务完成情况**

   - 显示条件: 始终显示
   - 数据来源: 任务配置和完成记录
   - 内容: 各任务的完成率

#### 优先级2: 条件存在的得分板块 (有数据时显示)

4. **客观题得分分析**

   - 显示条件: 课程中有客观题 && 有学生完成
   - 数据来源: 客观题提交记录
   - 内容: 平均分、得分分布、题目分析
5. **主观题批改情况**

   - 显示条件: 课程中有主观题 && (启用AI批改 || 教师已批改)
   - 数据来源: 主观题批改记录
   - 内容: 已批改数量、平均分、待批改列表

#### 优先级3: 可选的能力评估板块 (配置时显示)

6. **学科能力分布**

   - 显示条件: 教师配置了学科能力维度
   - 数据来源: AI能力评估
   - 内容: 各学科能力维度的星级分布
7. **跨学科能力分布**

   - 显示条件: 教师配置了跨学科能力维度
   - 数据来源: AI能力评估
   - 内容: 跨学科能力维度的星级分布
8. **AI发现的能力表现**

   - 显示条件: AI识别到额外能力表现
   - 数据来源: AI实时观察
   - 内容: AI识别的能力、置信度、学生列表

### 3.2 板块显示状态机

```typescript
enum BlockDisplayState {
  ALWAYS_SHOW = 'always_show',        // 始终显示
  SHOW_WHEN_DATA = 'show_when_data',  // 有数据时显示
  SHOW_WHEN_CONFIG = 'show_when_config', // 配置时显示
  HIDDEN = 'hidden'                   // 隐藏
}

interface BlockConfig {
  id: string;
  name: string;
  priority: number;  // 1-10, 数字越小优先级越高
  displayState: BlockDisplayState;

  // 显示条件判断函数
  shouldDisplay: (context: DisplayContext) => boolean;

  // 空状态提示
  emptyStateMessage?: string;
}

// 显示上下文
interface DisplayContext {
  courseConfig: CourseConfig;        // 课程配置
  studentData: StudentData[];        // 学生数据
  hasObjectiveQuestions: boolean;    // 是否有客观题
  hasSubjectiveQuestions: boolean;   // 是否有主观题
  hasCompetencyConfig: boolean;      // 是否配置了能力维度
  hasSubjectDimensions: boolean;     // 是否配置了学科维度
  hasCrossDisciplinaryDimensions: boolean; // 是否配置了跨学科维度
}
```

### 3.3 板块配置示例

```typescript
const blockConfigs: BlockConfig[] = [
  {
    id: 'class-overview',
    name: '班级概览',
    priority: 1,
    displayState: BlockDisplayState.ALWAYS_SHOW,
    shouldDisplay: () => true,
  },

  {
    id: 'student-status',
    name: '学生状态分布',
    priority: 2,
    displayState: BlockDisplayState.ALWAYS_SHOW,
    shouldDisplay: () => true,
  },

  {
    id: 'task-completion',
    name: '任务完成情况',
    priority: 3,
    displayState: BlockDisplayState.ALWAYS_SHOW,
    shouldDisplay: () => true,
  },

  {
    id: 'objective-scores',
    name: '客观题得分分析',
    priority: 4,
    displayState: BlockDisplayState.SHOW_WHEN_DATA,
    shouldDisplay: (ctx) => ctx.hasObjectiveQuestions && ctx.studentData.some(s => s.objectiveScores),
    emptyStateMessage: '课程中无客观题，或学生尚未完成客观题'
  },

  {
    id: 'subjective-grading',
    name: '主观题批改情况',
    priority: 5,
    displayState: BlockDisplayState.SHOW_WHEN_DATA,
    shouldDisplay: (ctx) => ctx.hasSubjectiveQuestions && ctx.studentData.some(s => s.subjectiveScores),
    emptyStateMessage: '课程中无主观题，或主观题尚未批改'
  },

  {
    id: 'subject-competencies',
    name: '学科能力分布',
    priority: 6,
    displayState: BlockDisplayState.SHOW_WHEN_CONFIG,
    shouldDisplay: (ctx) => ctx.hasSubjectDimensions,
    emptyStateMessage: '未配置学科能力维度'
  },

  {
    id: 'cross-disciplinary-competencies',
    name: '跨学科能力分布',
    priority: 7,
    displayState: BlockDisplayState.SHOW_WHEN_CONFIG,
    shouldDisplay: (ctx) => ctx.hasCrossDisciplinaryDimensions,
    emptyStateMessage: '未配置跨学科能力维度'
  },

  {
    id: 'ai-discovered-competencies',
    name: 'AI发现的能力表现',
    priority: 8,
    displayState: BlockDisplayState.SHOW_WHEN_DATA,
    shouldDisplay: (ctx) => ctx.studentData.some(s => s.detectedCompetencies?.length > 0),
    emptyStateMessage: 'AI尚未识别到额外能力表现'
  }
];
```

**方案： 仅从主观题评估能力**

### 4.5 跨学科维度不存在的情况

**场景**: 不同学科有不同的能力维度体系，某个学科可能没有通用的跨学科维度

**示例**:

- **数学课**: 数学运算能力、逻辑推理能力、空间想象能力

- **跨学科**: 批判性思维、创造性、信息整合、元认知

**问题**: 并非所有课程都需要跨学科维度评估

**解决方案**:

```typescript
interface SubjectCompetencyConfig {
  subjectId: string;
  subjectName: string;

  // 学科专属维度（必填）
  subjectDimensions: SubjectDimension[];

  // 跨学科维度（可选）
  crossDisciplinaryDimensions?: CompetencyType[];

  // 是否启用跨学科评估
  enableCrossDisciplinaryAssessment: boolean;
}

// 示例1: 纯学科评估（数学课）
{
  subjectId: 'math',
  subjectName: '数学',
  subjectDimensions: [
    { id: 'calculation', name: '运算能力' },
    { id: 'logic', name: '逻辑推理' }
  ],
  enableCrossDisciplinaryAssessment: false  // 不评估跨学科能力
}

// 示例2: 学科+跨学科评估（项目式学习）
{

    { id: 'research', name: '研究能力' },
    { id: 'presentation', name: '展示能力' }
  ],
  crossDisciplinaryDimensions: [
```

**UI显示**:

```typescript
// UI组件
function DeltaIndicator({ delta }: { delta: DataDelta }) {
  return (
    <span className="delta-indicator">
      {delta.currentValue}
      {delta.trend === 'up' && (

      )}
    </span>
  );
}
```

## 八、总结与关键决策

### 8.1 核心设计理念

#### 1. 数据确定性驱动UI设计

- **不是所有数据都必然存在**: 能力维度是可选的，不是必需的
- **确定性分层**: 统计数据 > 得分数据 > 能力数据
- **动态板块**: 板块根据数据可用性动态显示/隐藏

#### 2. 初始数据保证

- **学生绑定课程时创建初始数据**: 避免空白页面
- **初始能力基线**: 所有能力维度初始为2星（及格水平）
- **等待首次评估**: 提供友好的等待提示

#### 3. 变动为主

- **每次课显示变动**: 而非绝对值
- **趋势提示**: ↑/↓/→ 清晰展示变化方向
- **对比班级平均**: 帮助教师快速识别异常

### 8.2 关键决策

#### 决策1: 能力维度的可选性

**决策**: 能力维度评估是**完全可选的**，未配置时不显示相关板块

**理由**:

- 客观题主要检测知识掌握，不一定涉及能力维度
- 简单题目 (如 1+1=?) 没有能力维度测评
- 教师可能不配置能力维度
- 不同学科有不同的评估需求

**影响**:

- 能力评估板块为可变板块
- 需要提供友好的引导和配置入口
- AI可以辅助推断能力维度（可选）

#### 决策2: 数据分层模型

**决策**: 将数据分为三层：必然存在、条件存在、完全可选

**理由**:

- 提高UI的健壮性，避免空白页面
- 优先展示确定性高的数据
- 引导教师配置可选数据

**影响**:

- 数据模型需要重构
- 板块显示逻辑需要重新设计
- 需要实现动态板块系统

#### 决策3: 初始数据与变动数据

**决策**: 学生绑定课程时创建初始数据，每次课主要显示变动

**理由**:

- 避免空白页面，提供友好的用户体验
- 变动数据更容易识别趋势
- 初始基线作为对比参考

**影响**:

- 学生绑定课程时需要创建初始数据
- 需要实现变动数据的计算逻辑
- UI需要支持变动提示

#### 决策4: 全班视角与学生视角分离

**决策**: 使用Tab切换，分离全班视角和学生视角

**理由**:

- 教师的两种不同使用场景：整体了解 vs 个体关注
- 避免信息过载，提高聚焦度
- 更符合教师的工作流

**影响**:

- 需要实现Tab切换
- 两个视角的数据加载和渲染需要分别优化
- 学生详情使用弹窗，避免页面跳转

#### 决策5: 客观题能力维度推断

**决策**: AI自动推断 + 教师确认（可选）

**理由**:

- 客观题也可能涉及能力维度
- 减轻教师配置负担
- AI推断可能不准确，需要教师确认

**影响**:

- 需要实现AI推断逻辑
- 需要提供教师确认界面
- 推断结果需要标注置信度

#### 决策6: 跨学科维度的可选性

**决策**: 跨学科维度是**完全可选的**，不同学科可以选择是否启用

**理由**:

- 不是所有课程都需要跨学科评估
- 学科专属维度可能更重要
- 给教师更大的灵活性

**影响**:

- 能力配置需要区分学科维度和跨学科维度
- UI需要分别展示两类维度
- 未启用时不显示跨学科板块
