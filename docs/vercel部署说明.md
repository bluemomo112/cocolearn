  对本地维护的影响

  好消息：不会影响本地开发

  Vercel 部署是完全独立的，原因：

1. 代码分离
   - Vercel 从 Git 仓库拉取代码部署
   - 本地代码和线上代码互不干扰
   - 你可以继续在本地正常开发
2. 环境隔离
   - 本地：npm run dev（开发环境）
   - Vercel：自动构建生产版本
   - 通过环境变量区分不同环境
3. 工作流程
   本地开发 → Git 提交 → 推送到 GitHub → Vercel 自动部署

  实际维护建议：

  推荐做法：
  // 使用环境变量控制功能
  const isProduction = process.env.NODE_ENV === 'production'
  const enableAI = process.env.NEXT_PUBLIC_ENABLE_AI === 'true'

  // 在 Vercel 上不配置 NEXT_PUBLIC_ENABLE_AI，AI 功能自动禁用
  if (enableAI) {
    // AI 功能代码
  }

  分支策略：

- main 分支 → Vercel 生产环境（不含 AI 功能）
- dev 分支 → 本地开发（含所有功能）
- 或使用环境变量在同一分支控制

  不会遇到的问题：

- ❌ 部署后本地无法运行
- ❌ 需要维护两套代码
- ❌ 配置冲突

  可能需要注意：

- ✅ 敏感信息（API 密钥）用环境变量管理
- ✅ 本地和线上使用不同的环境变量配置
- ✅ 某些功能可能需要条件渲染
