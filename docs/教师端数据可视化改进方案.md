## 一、改进概述

### 1.1 改进范围

本次改进聚焦于教师端的两个核心页面，强化**能力维度**的数据可视化：

| 改进页面           | 文件路径                                 | 改进目标                                                           |
| ------------------ | ---------------------------------------- | ------------------------------------------------------------------ |
| **教师主页** | `src/app/teacher/page.tsx`             | 在「教学洞察」Tab 中新增能力维度分析看板，展示跨课程的能力培养效果 |
| **结果视角** | `src/app/teacher/note-config/page.tsx` | 重构 Results 视角，提供全局能力分布 + 个体能力画像的双层分析       |

**改进核心**：

- 从单纯的"进度/得分统计"转向"能力培养可视化"
- 支持教师快速识别：班级整体能力短板、个体学生能力优势、跨课程能力成长轨迹
- 所有可视化必须基于**可采集的真实数据**

### 1.2 设计原则

#### 原则 1：数据可行性优先

**强约束**：所有可视化必须明确标注数据来源，无法采集的数据不纳入设计。

数据来源分类：

1. **已有数据**（可直接使用）：

   - 学生 ID、姓名、班级
   - 课程完成进度、学习时长
   - 任务提交状态、客观题得分
2. **可采集数据**（需新增采集逻辑）：

   - 对话记录（学生-AI 全部对话）
   - 行为日志（资源访问、停留时长、页面切换）
   - 主观题答案文本
   - AI 批改结果（含能力维度反馈）
   - 笔记内容
3. **需要 AI 生成的数据**：

   - 能力评估报告（`CourseCompetencyReport`）
   - 跨课程画像（`LearnerProfile`）

#### 原则 2：能力维度为中心

所有新增可视化围绕 **6 大能力维度**：

| 能力维度   | CompetencyType            | 说明                 |
| ---------- | ------------------------- | -------------------- |
| 批判性思维 | `critical_thinking`     | 质疑假设、评估证据   |
| 信息整合   | `information_synthesis` | 跨资源连接、总结归纳 |
| 元认知     | `metacognition`         | 自我反思、策略调整   |
| 提问质量   | `question_quality`      | 深层次问题           |
| 创造性     | `creativity`            | 新颖想法、新联系     |
| 坚持性     | `persistence`           | 持续努力、不放弃     |

可视化优先展示：

- **教师指定维度**（主观题配置的 `assignedCompetencies`）
- **AI 识别维度**（AI 在学习过程中发现的能力表现）

#### 原则 3：渐进式实现

**MVP 优先级**（参考设计文档第十章）：

| 优先级       | 功能                         | 说明               |
| ------------ | ---------------------------- | ------------------ |
| **P0** | 全局能力分布（教师指定维度） | 必须，核心价值     |
| **P0** | 个体能力雷达图 + 详细评价    | 必须，核心价值     |
| **P1** | AI 识别维度展示              | 重要，增强发现价值 |
| **P1** | 跨课程能力画像时间线         | 重要，体现长期成长 |
| **P2** | 学习轨迹可视化               | 可选，辅助分析     |

**暂不实现**（后续迭代）：

- AI 实时能力标记（先用课程结束评估）
- 教师审核/修改评估
- 更复杂的能力迁移学习

#### 原则 4：视觉层次清晰

- **全局视角**：柱状图/饼图展示班级分布，一眼看出整体趋势
- **个体视角**：雷达图 + 卡片式详情，深入了解单个学生
- **数据溯源**：每个评价提供证据链接（对话原文、笔记摘录）

### 1.3 数据可行性约束

#### 1.3.1 可采集的数据（基于设计文档第六章）

| 数据类型           | 具体内容                     | 采集时机            | 存储位置                       |
| ------------------ | ---------------------------- | ------------------- | ------------------------------ |
| **对话数据** | 消息内容、时间戳、AI能力标记 | 每条消息发送时      | ConversationLog 表             |
| **行为数据** | 资源访问、停留时长、任务交互 | 资源切换/任务提交时 | BehaviorLog 表                 |
| **产出数据** | 笔记、任务答案、反思内容     | 自动保存/提交时     | NoteContent、TaskSubmission 表 |
| **元数据**   | 学习时长、完成进度           | 会话结束时          | StudentNote 表                 |

#### 1.3.2 依赖 AI 生成的数据

| 数据                       | 生成时机           | 依赖输入                              |
| -------------------------- | ------------------ | ------------------------------------- |
| `CourseCompetencyReport` | 课程结束时（异步） | 对话记录 + 行为日志 + 任务结果 + 笔记 |
| `LearnerProfile`         | 课程评估完成后更新 | CourseCompetencyReport                |

**关键约束**：

- 能力评估报告需要 **完整的学习数据**，学生未完成课程时无法生成
- 跨课程画像需要 **至少 1 门课程的评估结果**

#### 1.3.3 暂不可行的可视化

以下可视化因数据源不明确或采集成本过高，**暂不纳入 MVP**：

| 可视化需求       | 不可行原因                         | 替代方案                        |
| ---------------- | ---------------------------------- | ------------------------------- |
| 学生情绪变化曲线 | 需要实时情绪识别，成本高且准确度低 | 用 AI 识别的"困惑/质疑"标记代替 |
| 学生注意力热力图 | 需要眼动追踪或鼠标轨迹，采集复杂   | 用资源停留时长代替              |
| 社交互动网络图   | 当前无学生间协作功能               | 暂不实现                        |

## 二、教师主页可视化改进

### 2.1 当前状态分析

#### 2.1.1 现有功能盘点

教师主页当前有4个Tab：我的课程、教学洞察、知识库、成长档案。其中**「教学洞察」Tab**是本次改进的重点。

**现有「教学洞察」内容**（`src/app/teacher/page.tsx` - TeachingInsights 组件）：

```typescript
// 现有数据展示（第533-693行）
├── 关键指标卡片 (Key Metrics) - 4个
│   ├── 平均完成率: 78% (+5%)
│   ├── 学生满意度: 4.6 (+0.2)
│   ├── 互动频率: 23次/课 (+3)
│   └── 作业提交率: 92% (-2%)
│
├── 课程表现对比表格 (Course Performance)
│   ├── 列: 课程名称、完成率、满意度、互动率
│   ├── 数据: 4门课程的横向对比
│   └── 可视化: 进度条、星级、百分比标签
│
└── AI 教学建议 (AI Suggestions) - 3条
    ├── 类型: improvement / success / warning
    ├── 内容: 针对特定课程的建议
    └── 交互: 查看建议/生成报告/查看详情按钮
```

#### 2.1.2 现有设计的不足

| 问题                         | 具体表现                                     | 影响                         |
| ---------------------------- | -------------------------------------------- | ---------------------------- |
| **缺乏能力维度视角**   | 仅展示完成率、满意度等结果性指标             | 教师无法了解学生能力培养效果 |
| **缺乏跨课程分析**     | 每门课程孤立展示，无法看到学生的能力成长轨迹 | 无法体现跨学科学习的核心价值 |
| **缺乏个体洞察入口**   | 只有班级整体统计，无个体学生的能力画像入口   | 教师难以针对性指导           |
| **AI建议缺乏数据支撑** | 建议内容是静态Mock数据，未与能力评估关联     | 建议缺乏说服力               |

#### 2.1.3 改进目标

本次改进将在「教学洞察」Tab中**新增「能力培养看板」**，实现以下目标：

1. **全局能力分布**：展示所有课程中学生在各能力维度的分布情况
2. **跨课程能力趋势**：追踪学生在多门课程中的能力成长轨迹
3. **个体能力快照**：提供快速查看优秀/待提升学生的入口
4. **数据驱动建议**：基于能力评估数据生成AI建议

#### 2.2.2 详细改进说明

**改进点1：新增「能力培养全局视图」**

- **位置**：在现有4个指标卡片和课程表格之间插入
- **内容**：
  - 6个能力维度的分布柱状图（3个教师常用 + 3个AI识别）
  - 筛选器：课程范围、时间范围、学生群体
  - 每个维度显示4个等级（★~★★★★）的百分比分布
  - 班级平均等级标注
- **数据来源**：聚合所有 `CourseCompetencyReport` 中的能力评估结果
- **设计参考**：doc/自学模式-跨学科改造方案.md 第230-243行

**改进点2：新增「能力成长趋势图」**

- **位置**：能力全局视图下方
- **内容**：
  - 选择单个能力维度
  - 横轴：按时间排列的课程
  - 纵轴：能力等级（★~★★★★）
  - 折线/散点图展示班级中学生的分布演变
  - AI生成的趋势洞察
- **数据来源**：`LearnerProfile.globalCompetencies[type].history`
- **交互**：点击数据点可查看该课程的详细报告

**改进点3：新增「需要关注的学生」**

- **位置**：趋势图下方
- **内容**：
  - 能力待提升学生列表（< ★★）
  - 能力突出学生列表（≥ ★★★★）
  - 显示学生数量和姓名预览
  - 点击[查看详情]跳转到「结果视角-个体视角」
- **数据来源**：实时计算 `LearnerProfile.globalCompetencies` 中的等级

**改进点4：增强「AI 教学建议」**

- **现状**：Mock的静态建议
- **改进**：基于能力评估数据生成
- **示例**：
  - "您的学生在「批判性思维」上平均提升了0.5星，建议继续加强证据引用训练"
  - "12名学生的「信息整合」能力低于★★，建议在下次课程中增加跨资源对比任务"

## 五、技术实现建议

### 5.1 组件库选择

#### 5.1.1 图表库推荐

**方案一：Recharts（推荐）**

- **优点**：
  - React 原生支持，组件化API
  - 响应式设计，支持移动端
  - 文档完善，社区活跃
  - 支持柱状图、雷达图、折线图等常用图表
- **缺点**：
  - 定制化能力相对较弱
- **适用场景**：全局能力分布、跨课程趋势图

**方案二：Apache ECharts（备选）**

- **优点**：
  - 功能强大，图表类型丰富
  - 定制化能力强
  - 性能优秀
- **缺点**：
  - React 集成需要额外封装
  - API 较复杂
- **适用场景**：复杂的数据可视化需求

**建议**：MVP 阶段使用 **Recharts**，后续有复杂需求再引入 ECharts。

#### 5.1.2 UI 组件库

当前项目已使用 **Tailwind CSS** + **Lucide Icons**，建议继续使用。

**新增组件需求**：

- 可展开/折叠的卡片组件（Accordion）
- 雷达图容器
- 能力评级显示组件（星级）

**实现方式**：

- 使用 **Headless UI** 或 **Radix UI** 提供无样式的交互逻辑
- 用 Tailwind CSS 自定义样式

### 5.3 性能优化建议

#### 5.3.1 数据加载优化

**问题**：能力评估数据可能很大（包含完整对话记录、证据等）

**优化方案**：

1. **分页加载**：

   - 全局视角的学生列表分页显示（每页20条）
   - 个体视角的历史记录分页显示
2. **懒加载**：

   - 能力详情卡片默认折叠，展开时才加载详细证据
   - 学习轨迹默认收起，点击才加载
3. **数据缓存**：

   - 全局视角数据缓存5分钟（教师端）
   - 个体视角数据缓存10分钟

#### 5.3.2 AI 评估性能优化

**问题**：课程结束评估需要调用多次 LLM，耗时较长

**优化方案**：

1. **异步任务**：

   - 课程结束时触发异步评估任务
   - 学生端显示「评估生成中」状态
   - 评估完成后通知学生
2. **批量评估**：

   - 同一课程的多个学生批量评估
   - 复用相同的资源上下文
3. **增量评估**（可选，后续优化）：

   - 每完成一个阶段评估一次
   - 课程结束时只需整合各阶段评估

#### 5.3.3 前端渲染优化

**优化方案**：

1. **虚拟滚动**：

   - 学生列表超过100条时启用虚拟滚动
   - 使用 `react-window` 或 `react-virtualized`
2. **图表懒加载**：

   - 能力雷达图仅在进入视口时才渲染
   - 使用 Intersection Observer API
3. **防抖/节流**：

   - 搜索/筛选操作使用防抖（300ms）
   - 图表交互（hover）使用节流（100ms）
