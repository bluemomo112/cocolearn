## 1. 核心设计理念

### 1.1 为什么传统评估不适合跨学科学习？

| 传统评估 | 跨学科学习评估 | 差异原因 |
|---------|--------------|---------|
| **评估对象**：知识点掌握 | **评估对象**：能力/思维/素养 | 跨学科强调迁移能力，不是记忆 |
| **评估方式**：客观题打分 | **评估方式**：过程性观察+语义分析 | 能力无法用对错判断 |
| **评估粒度**：单个概念 | **评估粒度**：综合表现 | 思维是整体的，不是碎片化的 |
| **评估结果**：85分 | **评估结果**："展现出强烈的质疑精神" | 描述性评价更有指导意义 |
| **数据存储**：按课程隔离 | **数据存储**：跨课程累积 | 能力是可迁移的 |

### 1.2 新评估体系的三大支柱

```
┌─────────────────────────────────────────────────────────────┐
│  支柱1：能力维度体系 (Competency Framework)                  │
│  - 定义跨学科的核心能力（批判性思维、创造性等）                │
│  - 每个能力有明确的行为特征                                   │
├─────────────────────────────────────────────────────────────┤
│  支柱2：语义化评估引擎 (LLM-based Assessment)                │
│  - 通过大模型分析学生的对话、笔记、任务表现                    │
│  - 输出描述性评价 + 量化维度                                  │
├─────────────────────────────────────────────────────────────┤
│  支柱3：跨课程能力画像 (Learner Profile)                     │
│  - 全局累积学生的能力数据                                     │
│  - 支持迁移学习（课程A的表现影响课程B的策略）                 │
└─────────────────────────────────────────────────────────────┘
```

## 2. 能力维度体系

### 2.1 核心能力列表（可选配）

**设计原则**：不是所有课程都评估所有维度，教师可选择关注的能力。

#### 维度1：批判性思维 (Critical Thinking)

**定义**：质疑假设、评估证据、识别逻辑漏洞的能力。

**行为特征**（如何识别）：
- 学生在对话中提出"为什么"类问题
- 学生质疑资料中的观点（如："这个说法有依据吗？"）
- 学生比较不同来源的信息，发现矛盾
- 学生要求证据或推理过程

**评估方式**：
1. **对话分析**：统计学生质疑性问题的比例
2. **LLM判断**：分析对话内容，判断学生的质疑深度
3. **任务表现**：主观题中是否展现了多角度思考

**数据来源**：
- 对话记录（主要）
- 笔记内容（学生是否记录了反驳观点）
- 任务提交（如：辩论、案例分析）

**有什么用**：
- **教师端**：看到哪些学生具备质疑精神，哪些学生习惯被动接受
- **学生端**：帮助学生认识到"我在这门课中学会了质疑"
- **Manager端**：如果学生批判性思维弱，可以引入苏格拉底式Agent

**量化方式**（供可视化）：
- **等级**：初现（★）、发展中（★★）、熟练（★★★）、卓越（★★★★）
- **趋势**：上升/稳定/下降
- **跨课程对比**：在课程A中是★★★，在课程B中是★★

**成本**：
- LLM调用：每次课程结束后1次综合评估（~1000 tokens）
- 实时监控：每5轮对话触发1次轻量评估（~300 tokens）
- **估算**：$0.01/学生/课

**效果**：
- ✅ 高：批判性思维有明确的语言特征（质疑、反问、要求证据）
- ✅ 可迁移：在不同课程中都适用
- ⚠️ 注意：需要区分"有效质疑"和"无意义抬杠"

---

#### 维度2：信息整合能力 (Information Synthesis)

**定义**：从多个资源中提取、连接、整合信息的能力。

**行为特征**：
- 学生在回答问题时引用了多个资源
- 学生发现不同资源之间的联系（如："资料A提到X，资料B的Y其实是同一个意思"）
- 学生能够用自己的话总结跨资源的内容
- 学生的笔记中出现跨资源的知识网络

**评估方式**：
1. **资源访问模式分析**：学生是否在短时间内访问多个资源
2. **对话引用分析**：学生在对话中是否提到"刚才看的XXX"
3. **LLM判断**：分析学生的回答/笔记，判断是否展现了整合
4. **笔记结构分析**：是否有跨资源的思维导图或对比表

**数据来源**：
- 资源访问日志（behaviorLog.resourceInteractions）
- 对话记录
- 笔记内容（Markdown解析）

**有什么用**：
- **教师端**：识别哪些学生善于整合，哪些学生只看单一资源
- **学生端**：鼓励学生"你在这节课中很好地连接了3个资料"
- **Manager端**：如果学生整合能力弱，可以主动提示"你可以结合刚才看的资料A和B来思考"

**量化方式**：
- **等级**：孤立学习（★）、初步整合（★★）、熟练整合（★★★）、创造性整合（★★★★）
- **指标**：跨资源引用次数、信息连接数

**成本**：
- 行为分析：基于日志，几乎无成本
- LLM判断（笔记）：每次课程结束后1次（~800 tokens）
- **估算**：$0.005/学生/课

**效果**：
- ✅ 中高：行为特征相对明显（访问多个资源、对话中引用）
- ✅ 跨课程有效：不同学科都需要整合能力
- ⚠️ 注意：需要区分"有效整合"和"简单拼凑"

---

#### 维度3：元认知能力 (Metacognition)

**定义**：对自己学习过程的监控、评价和调整能力。

**行为特征**：
- 学生主动反思（如："我发现我刚才理解错了"）
- 学生调整学习策略（如："这样学不下去，我换个方式"）
- 学生评价自己的理解程度（如："这部分我还不太懂"）
- 学生设定学习目标或检查点

**评估方式**：
1. **对话分析**：识别元认知性语言（"我觉得"、"我发现"、"我应该"）
2. **行为模式分析**：学生是否在遇到困难后调整策略（如：换资源、换提问方式）
3. **反思任务**：教师设置反思环节（如："总结你的学习过程"），LLM评估质量

**数据来源**：
- 对话记录（元认知性语言）
- 行为日志（学习策略调整）
- 反思任务提交

**有什么用**：
- **教师端**：识别哪些学生缺乏自我监控（盲目学习）
- **学生端**：帮助学生意识到"我的元认知在提升"
- **Manager端**：如果学生元认知弱，主动引导反思（如："你觉得刚才学得怎么样？"）

**量化方式**：
- **等级**：被动学习（★）、初步觉察（★★）、主动监控（★★★）、策略性调整（★★★★）
- **指标**：元认知性语言频率、策略调整次数

**成本**：
- 对话分析（关键词匹配）：几乎无成本
- LLM深度分析（反思任务）：每次1次（~600 tokens）
- **估算**：$0.003/学生/课

**效果**：
- ✅ 高：元认知语言特征明显
- ✅ 教育价值大：元认知是"学会学习"的核心
- ⚠️ 注意：需要教师在Workflow中设计反思环节，否则数据不足

---

#### 维度4：提问质量 (Question Quality)

**定义**：提出有深度、有针对性问题的能力。

**行为特征**：
- 问题从事实性（what）向解释性（why）、应用性（how）演进
- 问题有明确的上下文（不是泛泛而问）
- 问题反映了思考深度（如："如果改变X，Y会怎样？"）

**评估方式**：
1. **问题分类**：使用LLM将问题分类为 what/why/how/hypothetical
2. **问题复杂度评分**：LLM评估问题的深度（1-5分）
3. **问题演进分析**：跟踪学生问题质量的变化趋势

**数据来源**：
- 对话记录（所有学生提问）

**有什么用**：
- **教师端**：看到学生的提问能力成长
- **学生端**：鼓励学生"你的问题越来越有深度了"
- **Manager端**：如果学生只问浅层问题，Agent可以引导"你能想想为什么吗？"

**量化方式**：
- **等级**：浅层提问（★）、描述性提问（★★）、解释性提问（★★★）、创造性提问（★★★★）
- **指标**：why/how问题占比、平均问题复杂度

**成本**：
- LLM分类：每个问题1次调用（~100 tokens/问）
- 如果学生问20个问题：~2000 tokens
- **估算**：$0.005/学生/课

**效果**：
- ✅ 高：问题类型有明确的语言特征
- ✅ 实时可用：可以在对话过程中实时反馈
- ⚠️ 注意：有些学生不爱提问，数据可能不足

---

#### 维度5：创造性 (Creativity)

**定义**：提出新想法、新联系、新视角的能力。

**行为特征**：
- 学生提出了教材/资料中没有的观点
- 学生进行了跨领域类比（如："这个现象像不像经济学中的XXX？"）
- 学生设计了原创的解决方案或作品
- 学生的笔记中出现了独特的组织方式或视觉化

**评估方式**：
1. **LLM新颖性判断**：对比学生的回答/笔记与原始资料，判断原创程度
2. **类比识别**：识别学生是否使用了隐喻、类比
3. **作品评估**：如果任务是创作类（设计、代码、方案），LLM评估创新性

**数据来源**：
- 对话记录
- 笔记内容
- 创作型任务提交

**有什么用**：
- **教师端**：识别有创造性思维的学生
- **学生端**：鼓励学生"你的想法很独特"
- **Manager端**：如果课程目标是培养创造性，可以推送"你能想出不一样的方法吗？"

**量化方式**：
- **等级**：复述为主（★）、部分改编（★★）、新颖观点（★★★）、原创性突破（★★★★）
- **指标**：原创内容比例、类比使用次数

**成本**：
- LLM新颖性判断：每次课程结束后1次（~1000 tokens）
- **估算**：$0.01/学生/课

**效果**：
- ⚠️ 中：创造性难以量化，主观性强
- ✅ 教育价值高：跨学科学习强调创新
- ⚠️ 注意：需要有开放性任务，否则无法展现

---

#### 维度6：坚持性 (Persistence)

**定义**：面对困难时持续尝试、不轻易放弃的能力。

**行为特征**：
- 学生遇到难题后，多次尝试不同方法
- 学生在困惑后没有立即放弃，而是继续提问/查阅资料
- 学生在任务中多次修改、迭代

**评估方式**：
1. **行为序列分析**：识别"遇到困难 -> 尝试 -> 失败 -> 再尝试"的模式
2. **时间跨度分析**：学生在同一问题上的投入时间
3. **LLM判断**：分析对话中是否有"不放弃"的语言特征

**数据来源**：
- 对话记录（困惑点 + 后续行为）
- 任务提交记录（修改次数、时间跨度）

**有什么用**：
- **教师端**：识别哪些学生容易放弃
- **学生端**：鼓励学生"你在这个问题上坚持了很久，很棒"
- **Manager端**：如果学生快速放弃，可以主动鼓励"再试试？"

**量化方式**：
- **等级**：易放弃（★）、部分坚持（★★）、持续尝试（★★★）、韧性强（★★★★）
- **指标**：困难问题的尝试次数、平均投入时间

**成本**：
- 行为分析：基于日志，几乎无成本
- LLM判断（可选）：每次课程结束后1次（~500 tokens）
- **估算**：$0.003/学生/课

**效果**：
- ✅ 中高：行为模式相对明显
- ✅ 教育价值大：成长型思维的重要指标
- ⚠️ 注意：需要有一定难度的任务，否则无法观察

---

#### 维度7：协作沟通能力 (Collaboration)（未来扩展）

**说明**：当前是单人学习，此维度暂不适用。但如果未来支持小组学习，可评估：
- 学生在讨论中的贡献

## 3. 语义化评估机制

### 3.1 什么是"语义化评估"？

**对比**：

| 传统评分 | 语义化评估 |
|---------|-----------|
| **输出**："学生得了85分" | **输出**："学生展现出强烈的质疑精神，能够主动寻找证据，但在整合多个资源时还需要更多练习" |
| **依据**：题目对错统计 | **依据**：LLM分析对话、笔记、任务的综合表现 |
| **可解释性**：低（为什么扣了15分？） | **可解释性**：高（明确指出优点和不足） |
| **指导性**：低（学生不知道如何改进） | **指导性**：高（告诉学生下一步该做什么） |

### 3.2 评估时机

#### 时机1：课程结束时（综合评估）

**目的**：生成完整的能力报告。

**流程**：
```python
def generate_course_competency_report(student_note_id):
    """课程结束时生成能力报告"""

    # 1. 收集所有数据
    student_data = {
        "conversations": get_all_conversations(student_note_id),
        "notes": get_student_notes(student_note_id),
        "tasks": get_completed_tasks(student_note_id),
        "behaviors": get_behavior_log(student_note_id),
        "resources": get_resource_interactions(student_note_id)
    }

    # 2. 获取教师关注的能力维度
    focused_competencies = get_teacher_config(student_note_id).focused_competencies
    # 例如：["critical_thinking", "information_synthesis", "metacognition"]

    # 3. 对每个维度进行语义评估
    competency_reports = {}

    for comp in focused_competencies:
        # 调用专门的评估Prompt
        report = llm_assess_competency(
            competency_type=comp,
            student_data=student_data,
            course_context=get_course_context(student_note_id)
        )
        competency_reports[comp] = report

    # 4. 生成综合报告
    final_report = llm_generate_summary(competency_reports, student_data)

    return final_report
```

**LLM Prompt示例**（批判性思维）：

```
你是一位教育评估专家。请根据以下学生数据，评估该学生的"批判性思维"能力。

## 评估维度：批判性思维
定义：质疑假设、评估证据、识别逻辑漏洞的能力。

行为特征：
- 提出质疑性问题
- 要求证据或推理过程
- 比较不同观点
- 发现矛盾或逻辑漏洞

## 学生数据

### 对话记录（部分）
{展示学生的20-30轮关键对话}

### 笔记内容
{展示学生的完整笔记}

### 任务表现
{展示学生的任务提交和得分}

### 行为数据
- 总学习时长：120分钟
- 访问资源数：5个
- 提问次数：18次
- 质疑性问题（初步识别）：6次

## 评估要求

请输出以下内容（JSON格式）：

1. **等级评定**（1-4星）：
   - ★ 初现：偶尔展现质疑，但不深入
   - ★★ 发展中：能提出质疑，但缺少证据支持
   - ★★★ 熟练：频繁质疑，并主动寻找证据
   - ★★★★ 卓越：系统性批判，能发现深层逻辑问题

2. **具体表现**（描述性，150字以内）：
   - 学生在哪些地方展现了批判性思维？举例说明。

3. **亮点**（1-2句话）：
   - 学生最值得肯定的表现。

4. **待提升领域**（1-2句话）：
   - 学生还需要改进的地方。

5. **建议**（1-2句话）：
   - 下一步如何提升批判性思维？

6. **支持证据**（列出3-5条关键证据）：
   - 例如：对话第12轮中，学生质疑了资料的数据来源。

输出格式：
{
  "rating": 3,
  "description": "...",
  "highlights": "...",
  "areas_for_improvement": "...",
  "suggestions": "...",
  "evidence": ["...", "...", "..."]
}
```

**成本**：
- Input tokens：~3000（数据摘要） + 500（Prompt） = 3500 tokens
- Output tokens：~500 tokens
- 单个维度：$0.01
- 如果评估3个维度：$0.03/学生/课

**输出示例**：


### 3.3 评估的准确性如何保证？

#### 策略1：多数据源交叉验证

**原则**：不依赖单一数据源。

```python
def assess_critical_thinking(student_data):
    """多维度验证"""

    scores = []

    # 维度1：对话分析
    conversation_score = analyze_conversations(student_data.conversations)
    scores.append({
        "score": conversation_score,
        "weight": 0.5,  # 权重50%
        "confidence": 0.8 if len(student_data.conversations) > 15 else 0.5
    })

    # 维度2：笔记分析
    notes_score = analyze_notes(student_data.notes)

        "weight": 0.3,

    task_score = analyze_tasks(student_data.tasks)
    scores.append({
        "score": task_score,
        "weight": 0.2,
        "confidence": 0.9  # 任务评分最可信
    })

    # 加权综合（考虑置信度）
    final_score = weighted_average(scores)
    final_confidence = average_confidence(scores)

    return {
        "score": final_score,
        "confidence": final_confidence,

    }
```

## 4. 跨课程能力画像

### 4.1 为什么需要跨课程画像？

**场景问题**：
- 学生在课程A中展现了很强的批判性思维，在课程B中Manager应该如何调整策略？
- 学生上了10门课，教师如何看到学生的**整体成长**，而非孤立的单课表现？
- 学校管理者如何评估"这个学生的综合素养"？

**答案**：构建**全局能力画像**（Learner Profile），跨课程累积。

### 4.2 数据结构设计

```typescript
interface LearnerProfile {

  globalCompetencies: {
```

### 4.3 数据累积机制

#### 课程结束时触发更新

```python
def update_learner_profile(student_id, course_competency_report):
    """课程结束后更新全局画像"""

    profile = get_learner_profile(student_id)

    # 1. 更新能力维度
    for comp_type, comp_report in course_competency_report.items():
        if comp_type not in profile.globalCompetencies:
            # 第一次评估该维度
            profile.globalCompetencies[comp_type] = {
                "overallRating": comp_report.rating,
                "history": [],
                "trend": "stable",
                "confidence": 0.3  # 只有一次数据，置信度低
            }

        # 添加历史记录
        profile.globalCompetencies[comp_type].history.append({
            "courseId": course_competency_report.course_id,
            "courseName": course_competency_report.course_name,
            "timestamp": now(),
            "rating": comp_report.rating,
            "evidence": comp_report.evidence[:3]  # 保留前3条关键证据
        })

        # 重新计算综合评级（时间加权）
        profile.globalCompetencies[comp_type].overallRating = \
            calculate_weighted_rating(profile.globalCompetencies[comp_type].history)

        # 计算趋势
        profile.globalCompetencies[comp_type].trend = \
            calculate_trend(profile.globalCompetencies[comp_type].history)

        # 更新置信度（数据越多，越可信）
        data_count = len(profile.globalCompetencies[comp_type].history)
        profile.globalCompetencies[comp_type].confidence = min(data_count / 5, 1.0)

        # 更新最新观察
        profile.globalCompetencies[comp_type].latestObservation = comp_report.description

    # 2. 更新学习风格（从行为推断）
    profile.learningStyle = infer_learning_style(student_id)

    # 3. 更新元数据
    profile.metadata.totalCoursesCompleted += 1

    save_learner_profile(profile)
```

#### 综合评级的计算（时间加权）

**原则**：最近的表现权重更高（学习是成长的）。

```python
def calculate_weighted_rating(history):
    """时间加权计算综合评级"""

    if not history:
        return 0

    weighted_sum = 0
    total_weight = 0

    for record in history:
        # 时间衰减因子（越近权重越高）
        days_ago = (now() - record.timestamp) / (24 * 3600)
        time_weight = exp(-days_ago / 90)  # 90天半衰期

        weighted_sum += record.rating * time_weight
        total_weight += time_weight

    return weighted_sum / total_weight if total_weight > 0 else 0
```

#### 趋势计算（成长 vs 退步）

```python
def calculate_trend(history):
    """计算能力趋势"""

    if len(history) < 2:
        return "stable"

    # 简单策略：比较最近3次和之前的平均值
    recent_avg = average([h.rating for h in history[-3:]])
    earlier_avg = average([h.rating for h in history[:-3]]) if len(history) > 3 else recent_avg

    if recent_avg > earlier_avg + 0.3:
        return "ascending"
    elif recent_avg < earlier_avg - 0.3:
        return "descending"
    else:
        return "stable"
```

## 6. 数据采集与处理

### 6.1 数据采集点

| 数据类型 | 采集时机 | 采集方式 | 存储位置 | 成本 |
|---------|---------|---------|---------|------|
| **对话记录** | 每次学生发送消息 | API记录 | PostgreSQL | 低 |
| **笔记内容** | 学生保存笔记时 | API记录 | PostgreSQL | 低 |
| **资源访问** | 打开/关闭资源时 | 前端埋点 | PostgreSQL | 低 |
| **任务提交** | 完成任务时 | API记录 | PostgreSQL | 低 |
| **页面行为** | 滚动、点击、停留 | 前端埋点 | Redis（临时）| 低 |
| **AI评估** | 课程结束时 | LLM调用 | PostgreSQL | 中 |

### 6.2 数据处理流程

```
原始数据
  ├─ 对话记录（未处理）
  ├─ 行为日志（未处理）
  └─ 任务数据（未处理）
        ↓
  [数据清洗]
        ↓
  结构化数据
  ├─ 对话分类（what/why/how）
  ├─ 行为模式识别（访问顺序、时长）
  └─ 任务得分统计
        ↓
  [LLM语义分析]
        ↓
  能力评估报告
  ├─ 批判性思维：★★★
  ├─ 信息整合：★★
  └─ 描述性评价
        ↓
  [跨课程聚合]
        ↓
  Learner Profile更新
```

### 6.3 隐私与安全

**问题**：学生数据如何保护？

**策略**：
1. **数据最小化**：只采集必要数据（不记录与学习无关的内容）
2. **匿名化**：LLM评估时可以去除学生姓名（用"学生A"代替）
3. **访问控制**：
   - 学生只能看自己的数据
   - 教师只能看自己班级的数据
   - 管理员可以看聚合统计（不看个人详情）
4. **透明化**：告诉学生"我们记录了什么"，学生有权查看和删除

## 7. 成本与效果分析

### 7.1 LLM调用成本详细估算

#### 场景1：单个学生完成一门课程

| 调用场景 | 调用次数 | Input Tokens | Output Tokens | 单次成本 | 小计 |
|---------|---------|--------------|---------------|---------|------|
| **对话交互**（学生问20个问题） | 20 | 1000 | 300 | $0.0055 | $0.11 |
| **提问分类**（20个问题） | 20 | 100 | 50 | $0.0006 | $0.012 |
| **课程结束综合评估**（3个能力维度） | 3 | 3500 | 500 | $0.014 | $0.042 |
| **Learner Profile更新**（LLM生成总结） | 1 | 2000 | 300 | $0.008 | $0.008 |
| **总计** | 44 | ~60k tokens | ~10k tokens | - | **$0.17/人/课** |

#### 优化后成本（使用Prompt Caching + 国产模型）

| 优化策略 | 成本降低 |
|---------|---------|
| **Prompt Caching**（OpenAI） | -50% |
| **对话用GPT-4o-mini** | -80%（对话部分） |
| **评估用国产模型**（文心4.0） | -70%（评估部分） |
| **按需触发**（提问分类不是每次都做） | -30% |

**优化后总成本**：**$0.05/人/课（¥0.35）**

#### 场景2：一个班级（30人）完成一门课程

- 单人成本：$0.05
- 班级成本：$1.5（¥10.5）

**成本可接受性**：
- ✅ 如果课程收费 ¥50/人，AI成本占比 < 1%
- ✅ 如果学校采购（年费），分摊后更低

## 8. 技术实现路径

### 8.1 数据库Schema设计

```sql
-- Learner Profile（跨课程全局画像）
CREATE TABLE learner_profiles (
  id UUID PRIMARY KEY,
  student_id UUID REFERENCES students(id),
  global_competencies JSONB,  -- 全局能力维度
  learning_style JSONB,        -- 学习风格
  metadata JSONB,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);

-- Course Competency Report（单课程能力报告）
CREATE TABLE course_competency_reports (
  id UUID PRIMARY KEY,
  student_note_id UUID REFERENCES student_notes(id),
  competency_type VARCHAR(50),  -- "critical_thinking", "information_synthesis"等
  rating INT,  -- 1-4星
  description TEXT,  -- 描述性评价
  highlights TEXT,
  areas_for_improvement TEXT,
  suggestions TEXT,
  evidence JSONB,  -- 支持证据
  ai_confidence FLOAT,  -- AI评估的置信度
  teacher_override JSONB,  -- 教师修改
  created_at TIMESTAMP
);

-- Conversation Log（对话记录）
CREATE TABLE conversations (
  id UUID PRIMARY KEY,
  student_note_id UUID,
  role VARCHAR(20),  -- "student" | "ai"
  content TEXT,
  metadata JSONB,  -- 问题类型、复杂度等
  created_at TIMESTAMP
);

-- Behavior Log（行为日志）
CREATE TABLE behavior_logs (
  id UUID PRIMARY KEY,
  student_note_id UUID,
  action_type VARCHAR(50),  -- "open_resource", "scroll", "highlight"
  resource_id UUID,
  metadata JSONB,
  created_at TIMESTAMP
);
```

## 附录：术语表

| 术语 | 定义 |
|------|------|
| **语义化评估** | 使用大模型分析学生表现，输出描述性评价而非简单打分 |
| **能力维度** | 跨学科学习关注的核心能力（批判性思维、信息整合等） |
| **Learner Profile** | 学生的全局能力画像，跨课程累积 |
| **描述性评价** | 文字描述学生表现，而非85分这样的数字 |
| **跨课程画像** | 学生在多个课程中的能力数据聚合 |
| **迁移学习** | 在课程A中学到的能力/风格，应用到课程B |
| **时间加权** | 最近的表现权重更高，因为学习是动态的 |
