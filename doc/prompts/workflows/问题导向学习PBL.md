# 问题导向学习(PBL)

## 工作流名称
PBL问题导向学习工作流

## 介绍
PBL(Problem-Based Learning)是一种以问题为驱动的学习方法。学生从一个真实或模拟的问题情境出发,自主探索、分析问题、寻找解决方案,在解决问题的过程中学习相关知识。

## 适用场景
- 学习具有应用性、实践性的内容
- 需要培养问题解决能力和综合运用能力
- 适合跨章节、综合性的学习主题

## 学习目标
- 培养问题分析和解决能力
- 学会自主探索和知识整合
- 提高学习的主动性和应用能力
- 体验从问题到知识的学习过程

## 工作流步骤

### 步骤1:问题呈现(Problem Presentation)
**目标:**呈现一个真实或模拟的问题情境,激发学习动机

**Agent配置:**
- **Agent类型:**案例分析题生成Agent(改编为问题呈现)
- **指令:**
  ```
  基于「{学习资料/主题}」,创建一个问题情境:

  **问题情境设计原则:**
  1. **真实性:**问题来自真实场景或合理的模拟情境
  2. **复杂性:**问题不能一眼看出答案,需要探索
  3. **开放性:**问题可能有多种解决方案或角度
  4. **关联性:**问题涉及本次学习的核心知识

  **问题情境结构:**
  ```json
  {
    "scenario": "问题情境描述(背景、人物、场景)",
    "problem_statement": "核心问题(清晰的问题陈述)",
    "context_info": "相关信息和数据",
    "questions_to_explore": [
      "需要探索的子问题1",
      "需要探索的子问题2",
      "需要探索的子问题3"
    ]
  }
  ```

  **示例:**
  主题:光合作用
  情境:你是一位农业顾问,某农场主发现他的温室大棚作物产量低于预期。你需要分析可能的原因并提出解决方案。
  问题:如何提高温室大棚作物的产量?
  子问题:
  - 温室环境中哪些因素会影响植物生长?
  - 光合作用与作物产量有什么关系?
  - 可以采取哪些措施优化光合作用效率?
  ```

**输出:**
- 问题情境描述
- 核心问题
- 探索子问题列表

**预计时间:**3-5分钟

---

### 步骤2:问题分析(Problem Analysis)
**目标:**分析问题,明确需要了解的知识和探索方向

**Agent配置:**
- **Agent类型:**苏格拉底式对话Agent
- **指令:**
  ```
  引导学生分析问题,而不是直接解决:

  **引导问题:**
  1. "面对这个问题,你的第一反应是什么?"
  2. "要解决这个问题,你觉得需要了解哪些知识?"
  3. "这个问题可以分解成哪几个小问题?"
  4. "你已经知道哪些相关信息?还有哪些是未知的?"
  5. "你打算从哪个角度入手分析?"

  **记录学生的分析:**
  - 学生认为需要了解的知识点
  - 学生提出的子问题
  - 学生的初步想法和假设

  **如果学生分析不够充分,继续引导:**
  - "你考虑了[角度A],那从[角度B]来看呢?"
  - "这个因素你提到了,但[另一个因素]是否也需要考虑?"

  最终整理出一个"学习探索清单"。
  ```

**输出:**
- 问题分析结果(需要了解的知识点)
- 探索方向和计划
- 学生的初步假设

**预计时间:**10-15分钟

---

### 步骤3:自主学习(Self-directed Learning)
**目标:**带着问题,自主从资料中寻找相关知识

**提示:**
```
现在,根据你的分析,开始自主学习。

**你需要探索的知识点:**
{列出步骤2中学生列出的知识点}

**学习建议:**
- 这不是从头到尾读资料,而是"带着问题找答案"
- 根据探索清单,有针对性地查找资料相关部分
- 记录找到的关键信息
- 思考这些信息如何帮助解决问题

**资料位置提示:**
{根据学生需要了解的知识点,提示资料的相关章节}

**学习过程中:**
- 可以随时呼出助教,询问概念或寻求引导
- 记得做笔记,记录关键信息

完成学习后,点击"下一步"。
```

**可配置对话Agent:**学生可随时提问(推荐:标准助教或循循善诱型)

**预计时间:**20-30分钟

---

### 步骤4:知识整合(Knowledge Integration)
**目标:**将学到的知识与问题联系,形成解决方案的思路

**Agent配置:**
- **Agent类型:**质疑者Agent
- **指令:**
  ```
  通过提问,帮助学生整合知识,形成解决方案:

  **引导整合:**
  1. "你学到了哪些关键知识?"(让学生列出)
  2. "这些知识和我们的问题有什么关系?"
  3. "根据这些知识,你对问题的分析有什么变化?"
  4. "你能将这些知识串联起来,形成解决思路吗?"

  **质疑和深化:**
  - 当学生提出想法时:"为什么你认为[方案]可行?"
  - "你的方案基于哪些知识点?"
  - "有没有考虑到[某个因素]?"
  - "如果[假设情况],你的方案还有效吗?"

  **引导学生思考:**
  - 不是简单应用知识,而是理解知识如何支撑解决方案
  - 考虑方案的可行性和局限性
  - 形成清晰的逻辑链条:知识→分析→方案

  记录学生的思路和解决方案雏形。
  ```

**输出:**
- 学生整合的关键知识
- 知识与问题的关联
- 初步的解决思路

**预计时间:**15-20分钟

---

### 步骤5:方案制定(Solution Development)
**目标:**制定具体的问题解决方案

**Agent配置:**
- **Agent类型:**辩论对手Agent
- **指令:**
  ```
  学生提出解决方案,你扮演挑战者,通过辩论完善方案:

  **要求学生:**
  "请详细说明你的解决方案:
  1. 你的方案是什么?(具体措施)
  2. 为什么这个方案可行?(理由和依据)
  3. 如何实施?(步骤)
  4. 预期效果是什么?"

  **你的挑战:**
  - **可行性挑战:**"你的方案在实际中可行吗?需要什么条件?"
  - **全面性挑战:**"你考虑了A,但B因素是否也需要考虑?"
  - **证据挑战:**"你说[方案]有效,依据是什么?资料中有支持吗?"
  - **替代方案挑战:**"除了这个方案,还有其他可能的解决方法吗?"
  - **局限性挑战:**"你的方案有什么局限性或潜在问题?"

  **当学生应对挑战时:**
  - 如果回应合理,认可:"这个论证很有力!"
  - 如果有疏漏,指出:"你可能需要补充考虑[XX]"

  最终,帮助学生形成一个经过论证的、较为完善的方案。
  ```

**输出:**
- 完整的解决方案
- 方案的理由和依据
- 方案的局限性和改进方向

**预计时间:**15-20分钟

---

### 步骤6:方案评估(Evaluation)
**目标:**评估方案的质量,反思学习过程

**Agent配置:**
- **Agent类型:**详细反馈批改Agent(改编为方案评估)
- **指令:**
  ```
  评估学生的问题解决方案:

  **评估维度:**
  1. **知识应用(30%):**是否正确运用了相关知识?
  2. **逻辑性(25%):**分析和推理是否严密?
  3. **全面性(25%):**是否考虑了多个角度和因素?
  4. **可行性(20%):**方案是否切实可行?

  **评分标准:**
  - 优秀(85-100):知识应用准确,逻辑严密,考虑全面,方案可行
  - 良好(70-84):主要知识点掌握,逻辑基本清晰,方案合理
  - 及格(60-69):有一定的知识应用,但不够全面或深入
  - 不及格(<60):知识应用有误或方案不可行

  **反馈格式:**
  ```json
  {
    "score": 总分,
    "strengths": ["优点1", "优点2"],
    "weaknesses": ["不足1", "不足2"],
    "suggestions": ["建议1", "建议2"],
    "knowledge_mastery": "对相关知识的掌握评价"
  }
  ```

  **鼓励和建议:**
  肯定学生的努力和创新,对不足之处给予建设性建议。
  ```

**输出:**
- 方案评分和详细反馈
- 知识掌握评价

**预计时间:**10-15分钟

---

### 步骤7:总结反思(Reflection)
**目标:**总结学到的知识,反思PBL学习过程

**提示:**
```
恭喜你完成了这次PBL问题导向学习!

**请花几分钟反思和总结:**

**1. 知识层面:**
- 为了解决「{问题}」,你学到了哪些核心知识?
- 用你自己的话,简要总结这些知识。

**2. 能力层面:**
- 这次学习,你的问题分析能力有提升吗?
- 在制定方案的过程中,你有什么收获?

**3. 方法层面:**
- PBL"从问题出发"的学习方式,和传统的"先学知识再应用"有什么不同?
- 你更喜欢哪种方式?为什么?
- 这种方法有什么优势和挑战?

**4. 如果重新来一次:**
- 你会在哪个环节做得更好?
- 有没有遗漏的角度或考虑不周的地方?

**你的学习记录:**
- 问题情境:「{问题情境}」
- 探索的知识点:{知识点列表}
- 最终方案得分:{得分}
- 方案核心:{方案概述}

**知识巩固建议:**
建议完成一个相关测试,巩固你在解决问题过程中学到的知识。

你的学习笔记和方案已自动保存。
```

**学生完成反思后,可选进入知识巩固测试**

**预计时间:**10分钟

---

### 步骤8:知识巩固(可选)
**目标:**通过测试巩固在PBL过程中学到的知识

**Agent配置:**
- **Agent类型:**题目生成Agent + 批改Agent
- **指令:**
  ```
  生成3-5道测试题,考查学生在PBL过程中学到的知识:

  **题目来源:**
  基于学生在步骤2中列出的"需要了解的知识点"。

  **题型:**
  - 2-3道客观题:考查基本概念理解
  - 1-2道主观题:考查应用和理解

  批改并反馈,巩固学习成果。
  ```

**输出:**测试得分和反馈

**预计时间:**10-15分钟(可选)

## 工作流总结

**总预计时间:**90-130分钟

**学习成果:**
- 通过解决真实问题,深度学习相关知识
- 培养问题分析、知识整合、方案制定能力
- 体验从"问题→知识→方案"的完整过程
- 提高学习的主动性和应用能力

**适合学生类型:**
- 喜欢探索和挑战,不满足于被动学习
- 有一定自主学习能力和逻辑思维能力
- 希望学以致用,将知识应用于实际问题

**PBL的优势:**
- **动机强:**真实问题激发学习动力,学习目的明确
- **深度学习:**为了解决问题,主动深入理解知识
- **能力培养:**不仅学知识,更培养问题解决能力
- **记忆牢固:**知识与问题情境关联,记忆更持久

**PBL的挑战:**
- 需要较强的自主学习能力
- 时间投入较多
- 可能需要跨章节整合知识

## 教师可配置项

**问题情境:**
- 教师自定义真实或模拟问题情境
- 或由系统根据资料自动生成

**问题复杂度:**
- 简单(涉及单一知识模块)
- 中等(推荐,涉及多个相关知识点)
- 复杂(需要跨章节整合知识)

**引导强度:**
- 高度引导(给较多提示和方向)
- 中度引导(推荐,平衡自主和支持)
- 低度引导(充分自主探索,适合高水平学生)

**方案评估标准:**
- 教师可自定义评分标准和权重
- 或使用系统默认标准

**是否包含知识巩固测试:**
- 必须完成
- 可选完成(推荐)
- 不包含
