# 自学模式：跨学科改造方案

> **核心转变**：从「知识点学习 + 复习曲线」转向「能力培养 + 语义化评估 + 跨课程画像」

---

## 一、现状问题诊断

### 1.1 当前设计的问题

| 问题                         | 现状                                                        | 影响             |
| ---------------------------- | ----------------------------------------------------------- | ---------------- |
| **缺乏跨学科特色**     | 当前设计更像通用学习工具，没有体现"能力/思维培养"的核心价值 | 产品无差异化     |
| **AI导师缺乏引导策略** | 没有定义AI如何根据上下文、学生能力画像来引导学生            | AI交互无差异化   |
| **评估体系缺失**       | 没有定义如何评估学生的能力表现                              | 无法闭环         |
| **结果视角简陋**       | 教师端结果视角只有基础统计，缺乏能力维度的全局和个体分析    | 教师难以把握学情 |

### 1.2 要砍掉/弱化的功能（学生端）

- ❌ **复习曲线/复习队列**：K12场景价值有限（学生端现有功能）
- ❌ **复习提醒**：K12场景价值有限（学生端现有功能）
- ⚠️ **概念掌握度雷达图**：改为「能力维度雷达图」（学生端现有功能）

---

## 二、整体改造方向

### 2.1 新的核心理念

```
┌─────────────────────────────────────────────────────────────────┐
│                      跨学科学习的三大支柱                         │
├─────────────────────────────────────────────────────────────────┤
│  1. 能力维度体系：                                                │
│     · 教师在主观题上指定关注的能力维度                            │
│     · AI在学习过程中自动识别和标记学生展现的能力                  │
│                                                                  │
│  2. AI导师引导策略：                                              │
│     · 能力引导策略内置于Agent人设/System Prompt中                 │
│     · 根据能力目标 + 学生画像，动态调整引导方式                   │
│                                                                  │
│  3. 语义化评估：                                                  │
│     · 课程结束时生成描述性能力报告                                │
│     · 累积到跨课程画像（Learner Profile）                         │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 改造范围总览

| 端               | 改造模块        | 改造内容                                         |
| ---------------- | --------------- | ------------------------------------------------ |
| **教师端** | 左侧-任务区     | 主观题增加「能力维度选择器」，客观题保持知识检测 |
| **教师端** | 中间-交互策略   | Agent人设中内置能力引导策略                      |
| **教师端** | 右侧-元认知监控 | 增加「能力评估预览」                             |
| **教师端** | 结果视角        | **重大改造**：全局能力分布 + 个体能力画像  |
| **学生端** | 中间-AI对话区   | AI根据能力目标+画像进行引导                      |
| **学生端** | 右侧-数据Tab    | 移除复习队列，改为「能力成长可视化」             |
| **后端**   | 新增            | Learner Profile（跨课程能力画像）                |
| **后端**   | 新增            | 课程结束时的能力评估Pipeline                     |
| **后端**   | 新增            | 学生行为数据采集                                 |

## 三、教师端改造详情

### 3.1 左侧栏改造：资源与任务

#### 3.1.1 资源区（保持不变）

- 上传PDF/Docx/Web/YouTube
- 知识锚点功能保留

#### 3.1.2 任务区（重要改造）

教师端任务区有**两种任务类型**：

**A. 客观题（Quiz）- 保持不变**

- 选择题（单选/多选）
- 用于**知识检测**，跨学科不妨碍简单的知识检测
- AI批改：自动判分

**B. 主观题（Assignment）- 新增能力维度选择器**

- 问答题、证据提交题
- 新增：**能力维度选择器**

### 3.2 中间栏改造：交互策略配置

#### 3.2.1 自由对话配置（调整）

**保留**：

- 角色选择（标准助教、苏格拉底等）
- 教师指令输入框
- 围栏开关

**关键调整**：能力引导策略**内置于Agent人设**

不再单独设置"AI引导强度"配置项。不同的Agent人设本身就包含了不同的引导策略：

| Agent人设      | 内置引导策略                 |
| -------------- | ---------------------------- |
| 标准助教       | 以回答为主，偶尔追问         |
| 苏格拉底导师   | 大量反问引导，很少直接给答案 |
| 批判性思维教练 | 专注于质疑和证据引导         |
| 循循善诱型     | 回答后追问，引导深入思考     |

教师通过选择不同的Agent人设，自动获得相应的引导策略。

#### 3.2.2 引导学习流配置（保持不变）

**保留**：

- 教学法选择（5E探究法等）
- 环节微调（user_prompt）

各阶段的能力培养目标可以**内置于教学法模板**中，教师无需手动配置。

### 3.3 右侧栏改造：产出与监控

#### 3.3.1 笔记模板（保持不变）

- 模板选择（空白 / 康奈尔 / 麦肯锡空雨伞）
- 提交要求开关

#### 3.3.2 元认知监控（小改）

**保留**：

- 监控策略选择（严格监督 vs 温柔陪伴）
- 干预阈值设置
- 教师自定义 user_prompt

**新增**：能力评估预览

## 五、学生端改造详情

### 5.1 左侧栏：资料面板（基本保持不变）

- 资源列表：保持不变
- 任务列表：保持不变

### 5.2 中间栏：AI对话学习区（核心改造）

#### 5.2.1 AI行为变化

**核心变化**：AI不再是单纯的问答机器，而是「能力培养导师」

| 场景     | 原来的AI   | 改造后的AI                                         |
| -------- | ---------- | -------------------------------------------------- |
| 学生提问 | 直接回答   | 回答后追问「你为什么这样想？」「你能找到证据吗？」 |
| 学生困惑 | 给出解释   | 引导学生自己发现「你觉得可能是什么原因？」         |
| 学生阅读 | 被动等待   | 主动提问「这个观点和之前的资料A有什么联系？」      |
| 阶段结束 | 无特殊行为 | 引导反思「你这个阶段学到了什么？」                 |

这些行为**内置于Agent人设的System Prompt**中。

#### 5.2.2 能力培养提示（示例）

```
┌─────────────────────────────────────────────────────────────┐
│  [AI对话区]                                                  │
│                                                              │

│                                                              │
│  AI：光合作用需要阳光、水、二氧化碳这三个基本条件。           │
│                                                              │
│      💭 我想追问你一下：                                      │
│      你觉得这三个条件中，哪个是最关键的？为什么？             │
│      （这个问题帮助你练习「批判性思维」——评估和比较）        │
│                                                              │
│  ─────────────────────────────────────────────────────────  │
│                                                              │
│  学生：我觉得阳光最重要，因为没有阳光就没有能量来源。         │

│      （寻找证据是批判性思维的重要部分）                       │
```

### 5.3 右侧栏：工作室（重要改造）

### 8.2 关键数据结构

#### 8.2.1 课程配置（教师端产出）

```typescript
interface CourseConfig {
  courseId: string;

  // 资源配置
  resources: Resource[];

  // 任务配置
  tasks: Task[];

  // 工作流配置
  workflow: WorkflowConfig;

  // 笔记模板
  noteTemplate: string;

  // Agent配置（引导策略内置于人设）
  agentConfig: {

    teacherInstruction?: string;  // 教师追加指令
    fenceMode: boolean;  // 围栏模式
  };

  // 元认知监控配置
  metacognitionConfig: {
    strategyId: string;  // 监控策略ID
    interventionRules: InterventionRule[];
    teacherPrompt?: string;
  };
}

interface Task {
  id: string;
  type: 'quiz' | 'assignment';  // 客观题 | 主观题
  title: string;
  content: string;

  // 仅主观题有此字段
  assignedCompetencies?: CompetencyType[];  // 教师指定的能力维度

  // AI批改配置
  gradingConfig?: {
    rubric?: string;  // 评分标准
    teacherPrompt?: string;  // 教师追加指令
  };
}

type CompetencyType =
  | 'critical_thinking'      // 批判性思维
  | 'information_synthesis'  // 信息整合
  | 'metacognition'          // 元认知
  | 'question_quality'       // 提问质量
  | 'creativity'             // 创造性
  | 'persistence';           // 坚持性

```

```
┌─────────────────────────────────────────────────────────────────────────┐
```

### 9.2 核心 Prompt 模板

#### 9.2.1 对话导师 System Prompt（苏格拉底导师人设示例）

```markdown
# Role: 苏格拉底式学习导师

你是一位采用苏格拉底式教学法的AI学习导师。你的核心方法是通过提问引导学生自己发现答案，而非直接告知。

## 核心教学原则

1. **少说多问**：尽量不直接给答案，而是通过问题引导
2. **循序渐进**：从学生当前理解水平出发，逐步深入
3. **能力培养**：在对话中培养批判性思维、信息整合等核心能力

## 你的行为准则

### 1. 当学生提问时
- 先确认学生当前的理解："你目前对这个问题是怎么理解的？"
- 引导学生思考："你觉得可能是什么原因？"
- 追问证据："你能从资料中找到支持的依据吗？"

### 2. 能力引导示例

**批判性思维引导**：
- "你为什么这样想？有什么证据支持吗？"
- "如果从另一个角度看，会怎么样？"
- "这个结论是怎么推导出来的？"

**信息整合引导**：
- "这个概念和我们之前看的资料A有什么联系？"
- "你能把这几个观点综合起来吗？"
- "不同资料对这个问题的看法一致吗？"

**元认知引导**：
- "你觉得自己理解了多少？哪里还有疑惑？"
- "你用了什么方法来学习这个内容？"
- "如果重新学，你会怎么做？"

### 3. 输出格式
回答时，如果需要追问，使用以下格式：

```

[简短回应或引导]

💭 让我问你一个问题：[追问问题]
（这个问题帮助你练习「批判性思维/信息整合/元认知」）

```
## 十一、关键决策点（待讨论）

### 11.1 能力维度选择

**建议MVP只做3个核心维度**：
1. 批判性思维
2. 信息整合
3. 元认知

**原因**：这3个维度有明确的行为特征，LLM评估准确度较高。

### 11.2 AI能力标记策略

**方案A**：实时标记（每轮对话后AI自动标记）
- 优点：数据更细粒度
- 缺点：增加API成本和复杂度

**方案B**：课程结束时回溯标记
- 优点：简单，成本低
- 缺点：无法实时反馈

**建议MVP采用方案B**，后续迭代再做实时标记。

### 11.3 评估触发时机

**建议课程结束时触发**：
- 实时评估成本高、准确度低
- 课程结束有完整数据，评估更准确

### 11.4 跨课程画像的使用

**建议MVP只展示，不用于迁移学习**：
- 先积累数据，验证评估准确性
- 后续再做AI根据画像调整引导策略
```
